# GithubAction을 통한 CD 도입 개요

## CD란 무엇인가?
CD의 경우 CI와 함께 소개되는 경우가 많습니다.  
CI/CD를 설명하기 위해서는 관습, 자동화, 세가지 키워드를 통하여 설명할 수 있을것 같습니다.

### CI
- 시점: 개발자가 신규 코드를 코드베이스에 합류시키는 시점
- 관습: 신규 코드를 최대한 자주 코드베이스에 합류시켜 코드를 안정적으로 관리
- 자동화: 테스트, 린트 등 코드를 검사할 수 있는 수단을 자동화 시켜 항시 코드 상태 관리
  
### CD(Delivery/Deployment)
- 시점: 배포 단계 혹은 항시 배포가능한 상황
- 관습: 소스 코드를 항상 배포 가능한 상태로 관리
- 자동화: CI에서 검증하는 부분 + 추가적인 배포를 위한 테스트 및 코드 관리(ex.엔드 투 엔드 테스트)

### 요약
간단하게 정리하자면  코드 통합, 배포 시점에 필요한 작업들을 자동화하여 코드를 안정적으로 관리할 수 있는 방법론입니다.

#### 한국 캐시워크 내 도입하려는 사항:  
현재 CI/CD를 통합적으로 한국 캐시워크 안드로이드 팀 내에 도입하기에는 무리가 있습니다.  
이에 CD중 테스트 배포 영역을 자동화시키고자 합니다.(CI/CD 개념 중 극히 일부분만 적용)

## 기대 효과
### ⏰ 개발자의 테스트 앱 배포 시간 단축
#### 도입이전 테스트 앱 배포 프로세스 (대략 18분 소요)
1. 테스트 앱 배포 요청 수신
2. 안드로이드 스튜디오를 통해 AAB 추출(대략 10분 소요)
3. 파이어베이스 콘솔을 통하여 테스트 앱 배포 및 릴리즈 노트 작성(대략 5분 소요)
4. 슬랙을 통해 필요한 관계자(QA팀, 관련 업무자)에게 노티(대략 3분 소요) 

#### 도입 후 테스트 앱 배포 프로세스 (대략 3분 소요)
1. 테스트 앱 배포 요청 수신
2. 템플릿에 맞춰 이슈 작성(3분 소요)

도입효과: 테스트 앱 배포 요청이 들어올떄 **15분** 가량의 시간을 자동화를 통해 확보가 가능합니다.

### 🤝 중간과정 자동화로 휴먼에러 제거
도입 이전 테스트 앱 배포 프로세스를 살펴보면 4단계를 거치기 때문에 각 단계별로 개발자가 실수할 수 있는 요소들이 많습니다.  
이부분의 단계를 줄이고 자동화 시킴으로써 휴먼에러가 날 수 있는 경우의 수 를 크게 낮출 수 있습니다.  
(다중으로 요청이 들어왔을때 처리능력 상승)
